# 角色固定偏好

当核心记忆已经包含称呼约定，模型仍可能沿用旧对话中的称呼。本功能把用户明确保存的当前偏好独立带入聊天请求，并可对页面内生成的可见文字做明确禁用词检查。

## 使用

记忆库 → 选择角色 → 核心 → 固定偏好。按角色填写允许称呼、禁用称呼和补充约定，开启后保存。示例按钮只填草稿，仍需用户保存；没有配置的角色默认关闭。

提示词查看器中的 `currentUserPreferences` 是独立规则，不依赖 `memoryCore` 预设槽位、向量检索或自动总结。用户更新的称呼约定优先于旧记录中的称呼，不会修改已有核心记忆、人设和世界书。

## 行为边界

- 私聊与群聊的在线页面生成：流式、非流式、文本工具和原生工具路径在正式保存文字和执行本轮动作之前检查；群聊按发言角色检查，整轮预检后再保存。
- 明确命中禁用词时保存为 UI 失败草稿，排除正式上下文和通知，可手动重新生成；不会自动发起额外模型请求或静默替换文字。流式预览可能此前已显示部分文字。
- 检查采用 NFKC 和去零宽后的明确字符串匹配。引用禁用词也可能触发；补充约定里的泛称、近义称呼不自动扩展成禁词。工具参数、思维链、状态和资源名不作为称呼检查对象。
- 线下聊天带入偏好提醒，暂无输出拦截。个人云新快照可携带规则，旧排期快照可能未更新；云端输出及原文导入暂无拦截。微信独立运行包本次未接入固定偏好。
- 原有云端兜底预约在本地结束或失败后撤销，尽力避免再生成；网络失败或云任务已经开始时仍存在既有竞态。

## 数据与维护

独立 KV 前缀：`ai_phone_character_preferences_v1:<characterId>`，纳入“记忆”备份模块，无新增数据库版本。每类称呼最多 8 项、每项 32 字，补充约定最多 600 字。标准化后允许与禁用同名会拒绝保存。

偏好编辑先确认 KV 水合，写入使用新增 `kvSetConfirmedAsync`，数据库成功后才发布缓存及保存事件；不改变既有乐观 KV 写入者。调用方需串行编辑同一个键，面板保存期间禁止重复操作。失败时旧缓存与回退值保留。

独立模块为 `lib/character-preferences.ts` 和 `lib/character-preference-error.ts`。上游更新时重点复核聊天构造器传参、assembler 的末尾 assistant prefill 与工具配对、正式回调前校验，以及备份前缀。若上游提供相同能力，应对照行为后减少私人补丁。

验证入口：`npm run check:preferences`。专项使用真实 TypeScript 函数与隔离存储/模型响应，不读取用户聊天或调用外部 API。
